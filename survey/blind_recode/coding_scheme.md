# Preregistered survey coding scheme

All six fields take one of `yes`, `no`, or `unclear`; use `unclear` whenever the available paper and supplement do not support a confident judgment, and never infer `no` from silence.

1. **Reports clean accuracy for source and target separately:** `yes` if clean accuracy (or clean error) is reported separately for every evaluated source and target, `no` if the paper explicitly reports only a pooled or otherwise non-separable clean result, and `unclear` if separate values cannot be located or their scope is ambiguous.
2. **Restricts transfer denominator to clean-correct inputs:** `yes` only if the paper states that the transfer denominator excludes inputs the target misclassified before attack (including “evaluated on correctly classified images”), `no` if it explicitly includes target-clean-incorrect inputs, and `unclear` if the denominator is unstated or ambiguous.
3. **Conditions on source attack success:** `yes` if the reported transfer denominator is explicitly restricted to adversarial examples that successfully attack the source model, `no` if the paper explicitly retains source-attack failures in that denominator, and `unclear` if source-success conditioning is unstated or ambiguous.
4. **Reports absolute counts, not only percentages:** `yes` if the numerator and denominator, an equivalent contingency count, or per-example records are available for every transfer rate used in the survey, `no` if the paper explicitly provides only percentages despite specifying the evaluated sample size insufficiently to recover exact counts, and `unclear` if exact counts may be recoverable but the reporting is ambiguous.
5. **States the L∞ or L2 budget numerically:** `yes` if every surveyed transfer result identifies a numerical perturbation radius and whether it is an $L_\infty$ or $L_2$ budget, `no` if a surveyed result explicitly has no bounded $L_\infty$ or $L_2$ budget, and `unclear` if the norm or numerical radius is missing or ambiguous.
6. **Releases artifacts sufficient to recompute (code plus checkpoints, or per-example outputs):** `yes` if a publicly accessible release provides executable evaluation code plus the required trained checkpoints or provides per-example clean, source-attacked, and target-attacked outcomes sufficient to recompute the conditioning quantities, `no` if the release explicitly lacks a required component, and `unclear` if no release is linked, access fails, or sufficiency cannot be established without assumptions.

For every judgment, the coding sheet records the supporting table, section, appendix, artifact path, or an explicit note that the relevant reporting could not be located. The unit of coding is the paper and its linked supplementary material as available on the coding date.
